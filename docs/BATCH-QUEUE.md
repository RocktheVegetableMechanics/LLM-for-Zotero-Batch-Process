# 批量论文队列

在“论文对话”中点击 Send 旁的“加入批量队列”。已打开队列时，再从其他论文点击该按钮即可追加；也可在 Zotero 文献列表多选后点击“添加文库选中项”，或拖入 Zotero 条目。重复论文会跳过。本地 PDF 需先导入 Zotero。

选择模型、推理力度和提示词后点击“开始 / 继续”。候选提示词包含 Summarize、Key Points、Methodology、Limitations、Diagram 和已保存的自定义提示词；修改已保存的快捷提示词后会刷新候选项。开始后固定本批的提示词正文，运行中追加的论文沿用该正文。

|按钮|行为|
|---|---|
|开始 / 继续|按顺序执行等待项；运行时禁用，避免重复启动|
|本篇完成后暂停|让当前论文完成保存，暂停领取下一篇；暂停后可修改下一篇使用的模型和推理力度|
|停止当前及后续|请求取消当前任务，停止等待项；保留已有会话|
|重新排队|将失败、未完成、已停止或中断项重新加入等待；开始后会建立新会话，旧会话保留|
|移出队列|移除尚未执行的等待项，不删除文献|
|打开论文会话|打开该任务实际使用的独立论文会话，可查看结果或错误|
|新建队列|当前队列完成或明确停止后清空任务列表，解锁提示词；不删除历史会话|
|收起 / 展开队列|隐藏或恢复管理区域，后台任务继续；运行时使用“收起”而非关闭|
|关闭|空闲时保存并关闭队列面板；重新打开会恢复队列并保持暂停|

拖动标题可移动窗口，拖动右下角可缩放。单篇模型失败会保留诊断并继续下一篇；队列落盘失败会暂停推进并显示错误。

## 重启和恢复

队列位于 Zotero profile 的 `llmforzotero/paper-batch-v1.json`。它包含文献标识、标题、已展开提示词、模型配置、状态和会话入口，不保存账号密钥；请按个人文库数据保管，不提交到 GitHub。两版使用相同格式。

重启后重新打开队列，等待项可以继续，原运行项显示“中断待确认”。先打开其会话检查是否已有结果，再决定是否重新排队，避免重复分析。已完成项的会话入口保留。

文献已删除或身份改变时，任务会报错；请移除或重新选择文献。模型配置无效时应先重新选择可用模型。队列文件为空或损坏时会报错并保留原文件；先备份文件，再修复 JSON 或将该文件移出队列目录后重新建队列。不要在 Zotero 正在运行队列时编辑文件。

本功能只在 Zotero 保持运行时执行。关闭 Zotero 后不会继续调用模型；恢复后不会自动重跑中断任务。
